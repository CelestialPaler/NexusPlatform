> 文档状态: Active
> 文档角色: 研发入口页 / 开发文档导航

## 1. 文档定位

本文档的目标不是替代所有开发专题文档，而是给研发人员提供一个稳定入口，帮助回答四个问题：

1. 当前仓库真实结构是什么。
2. 开发时应该先看哪些文档。
3. 常用开发与验证命令是什么。
4. 涉及版本、构建、跨平台、目录治理时，分别应该看哪里。

如果本文档与历史开发说明存在冲突，应优先以当前仓库结构和治理总纲为准。

## 2. 当前仓库结构

Nexus 当前是 monorepo，而不是单一桌面应用目录。

主分层如下：

1. `nexus-contracts`: 共享契约层
2. `nexus-core`: 逻辑实现层
3. `nexus-platform`: 桌面宿主层

关键路径如下：

1. GUI 启动入口: `nexus-platform/run.py`
2. 宿主后端: `nexus-platform/backend/`
3. 前端源码: `nexus-platform/frontend/src/`
4. 产品版本事实源: `nexus-platform/config/versions.json`
5. 统一构建入口: `build-system/build.py`
6. 构建 profile: `profiles/builds/`
7. 功能 profile: `profiles/features/`

## 3. 推荐阅读顺序

新加入项目的研发，建议按以下顺序阅读：

1. `00-设计概要.md`: 先理解项目定义、边界、版本状态和总体构成。
2. `development/11-Repository_Governance_Baseline.md`: 再理解当前工程治理边界。
3. `development/12-Documentation_Governance_and_Closure_Plan.md`: 理解 docs 自身的组织方式。
4. `development/05-Versioning_Strategy.md`: 理解当前版本事实源和同步规则。
5. 与任务相关的专题文档，例如跨平台、构建、契约层或变体工程文档。

## 4. 常用开发命令

### 4.1 前端构建

在 `nexus-platform/frontend/` 下执行：

```bash
npm ci
npm run build
```

### 4.2 统一构建计划校验

在仓库根目录执行：

```bash
python build-system/build.py --build-profile macos-demo --feature-profile demo --validate-readonly
```

或选择对应平台 / 档位的 profile 执行等价命令。

### 4.3 统一构建执行

在仓库根目录执行：

```bash
python build-system/build.py --build-profile windows-release --feature-profile full --execute
```

### 4.4 Python 侧最小验证

最小 CI 当前已围绕以下动作组织：

1. 安装 `nexus-contracts`、`nexus-core` 和 `nexus-platform` 依赖
2. 构建前端
3. `compileall`
4. 只读 build-plan 校验

## 5. 当前开发规则

### 5.1 结构边界

后续开发必须遵循以下依赖方向：

1. `nexus-platform` 可以依赖 `nexus-core`
2. `nexus-platform` 可以依赖 `nexus-contracts`
3. `nexus-core` 可以依赖 `nexus-contracts`
4. `nexus-core` 不应依赖 `nexus-platform`
5. `nexus-contracts` 不应依赖 `nexus-core` 或 `nexus-platform`

### 5.2 版本规则

当前产品版本只认：

1. `nexus-platform/config/versions.json` 中的 `app`

`nexus-core` 与 `nexus-contracts` 的版本分别由自身打包元数据维护，不应与产品版本混淆。

### 5.3 构建规则

当前真实构建入口是：

1. `build-system/build.py`

根目录脚本和其他包装脚本后续应尽量只保留薄包装角色，而不再承担事实标准入口角色。
